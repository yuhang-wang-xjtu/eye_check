# 发布规则

Windows、Android 和服务端独立维护版本。仅一端发生功能变更或修复时，只提升并发布该端版本；不得让其他端仅为对齐版本号而重新构建、提升版本或要求用户更新。

每次 GitHub Release 必须明确标注更新类型：`Windows`、`Android`、`服务端`，或实际涉及的平台组合。标题示例：`v0.5.2 · [Windows] 更新说明`。正文开头写清更新类型、涉及端的新版本及其他端是否需要更新。

发布附件只包含实际更新端的安装包或源码包及对应校验清单。未更新端保留原发布版本，可提供其最近一次发布链接，不复制或重新命名为本次版本。

只有协议兼容性或共同功能确实要求多端更新时才联合发布，并说明各端版本、兼容范围及升级顺序。

## 单端发布前的兼容要求

当前历史客户端通过 GitHub `releases/latest` 查询，并按 Release 标签寻找本平台安装包。正式开始拆分单端发布前，需要在相应客户端的下一次实际更新中适配按平台查找版本：跳过仅含其他平台附件的 Release，找到本平台最近的正式发布，比较本平台自身版本。不能把另一平台更新误报为本端新版本或下载错误。旧客户端的兼容处理也必须在发布前核对。

现有 `tools/package_release.ps1` 是联合打包脚本，要求 Windows 与 Android 版本一致。单端发布时须先调整为只校验、打包选定平台，不得为满足脚本约束而修改另一端版本。发布前核对附件、版本、校验清单和更新类型标注。

上述适配与相应平台后续实际功能更新一同交付；不为调整发布规则单独制造客户端版本更新。
