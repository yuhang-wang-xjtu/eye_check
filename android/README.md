# Android 原型 · 20·20·20

Kotlin + 原生 Activity/View。最低 Android 8.0，编译/目标 API 35，AGP 8.13.0、Kotlin 2.2.20、Gradle 8.14.3、JDK 17+。

## 功能

- 本地模式下亮屏工作每 20 分钟进入自动休息，默认 25 秒，可设 1–600 秒。开始和结束都发送通知，不弹出继续或停止确认框。
- 自动休息期间即使亮屏也不累计使用、久坐和连续工作时间；结束后亮屏自动开始下一轮 20 分钟计时。
- 久坐、连续工作、深夜提醒，默认或自定义提示音。
- 熄屏停止累计并按 5:1 回补，再次亮屏自动恢复；如果自动休息尚未结束则保留剩余休息时间。每日使用记录仅累计亮屏工作阶段，休息和回补不扣减历史。手动暂停仍可主动使用。
- 深浅色主题、可选悬浮倒计时、前台提醒服务和系统通知。
- 通知每秒更新剩余时间，数值下限为零；不使用会继续显示负数的系统 Chronometer。
- 可配置共享会话服务，访问令牌用 Android Keystore 加密保存。

## 构建

在 Android Studio 中打开此目录，使用兼容的 Gradle JDK（可选 Studio 自带 JBR），配置 Android SDK。也可以配置 JAVA_HOME 和 ANDROID_HOME 后执行：

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

Linux/macOS 使用 ./gradlew。APK 位于 app/build/outputs/apk/debug/app-debug.apk，使用开发者调试签名。发布覆盖更新必须保持签名一致并提高 versionCode；不得提交签名密钥。

打开应用时启动后台提醒，也可手动停止并在主页重新开启。请授予通知权限，并在设置中打开精确定时权限。护眼、久坐、连续工作、深夜及测试提醒均只通过系统通知发送，不打开应用内对话框或后台弹窗，也不要求点击继续。提醒通知中不提供继续、停止等选项。

悬浮窗权限仅用于可选的桌面悬浮倒计时，不是提醒所需权限。设置中的“5 秒后测试提醒”不改变计时，可点击后切到其他应用验证通知与声音。

精确定时按下一次真实提醒安排系统可见闹钟，不使用每分钟的空唤醒。没有精确定时权限时显示提示并降级，系统可能推迟送达。系统回收服务不等同于用户暂停；强制停止和厂商后台电池限制仍可能影响提醒。

本地亮屏状态使用系统交互状态与屏幕开关广播监测，不依赖回到本应用或解锁。后台延迟送达时，仅累计原工作截止时间之前的使用，从实际提醒时开始完整休息；休息结束后发送一次结束通知并根据屏幕状态自动继续或回补。

自动休息期间熄屏不会取消结束通知，再亮屏也不会提前跳过休息。结束时仍熄屏则保持回补，直到亮屏才工作；熄屏时的健康计时回补只结算一次。旧版本保存的自动休息保留原截止时间，不直接跳回工作。屏幕状态接口见 [Android PowerManager](https://developer.android.com/reference/android/os/PowerManager#isInteractive())。

## GitHub 更新

设置页“检查 GitHub 更新”访问固定仓库 yuhang-wang-xjtu/eye_check 的正式 Release。仅在用户主动检查时请求，按数字比较版本，跳过草稿、预发布和降级；网络失败和限流会显示提示。

确认后由 DownloadManager 下载并显示进度。完成后返回应用确认安装；安装前核对 SHA-256、大小、包名、版本号和签名，再请求系统安装权限并打开安装器。覆盖安装保留设置和记录，卸载会删除记录。更新过程不占用提醒服务线程。

发布 tag 格式为 v主版本.次版本.修订号，附件名为 EyeBreak-Android-v主版本.次版本.修订号.apk。版本比较、下载地址限制及哈希格式有单元测试；完整安装交互仍需真机验证。

参考：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[DownloadManager](https://developer.android.com/reference/android/app/DownloadManager)。

## 同步

不预置服务器地址或令牌。参考协议和服务见 [sync/](../sync/README.md)，需自行部署 HTTPS 后填写服务地址、共享会话标识及令牌。仅本地调试地址 localhost、127.0.0.1、模拟器宿主 10.0.2.2 允许 HTTP。

协议 v3 将本机使用状态与共同倒计时分开：只要电脑或手机任意一台在使用，两端共同倒计时就减少；全部都休息才一起按 5:1 回补。手机亮屏只将手机标记为使用，不把电脑标记为使用；电脑需要自己的新输入。界面和常驻通知同时显示本机状态与共同计时方向，约每秒同步同一服务器截止时间。

本地历史与同步缓存分开，离线区间暂不回填。手机熄屏撤销本机使用；如果电脑还在使用，共同计时继续倒数而不回补。屏幕事件排队补发，失联设备心跳超过 30 秒后不再算作正在使用。两端与服务端均需升级，旧 V1/V2 保留兼容路由，首次迁移保留旧统计。

自动休息仍默认 25 秒且不累计，不能由亮屏跳过。锁屏不会取消结束通知：收到休息截止时间后保留系统闹钟，在本地到点发送一次结束通知；服务端的持久完成序号用于重连补发与去重，不会被电脑先查询而消耗。已收到的周期在临时断网时仍能提醒；未收到的周期无法离线获知。系统闹钟的异步联网使用 goAsync 保持接收器生命周期，不因退出接收回调丢失结果。

## 平台限制

本地工作阶段以亮屏作为使用的近似判据，不追踪其他 App 的触控内容；观看视频或停留在亮屏锁屏界面也视为使用。自动休息期间和非交互的息屏显示不算使用。后台只发送通知，不强抢其他应用前台。

强制停止、未启动服务和厂商省电策略可能影响提醒；不申请开机自启。真实设备上的后台、省电、外设及安装兼容性仍需验证。
